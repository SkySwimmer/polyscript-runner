# Shellscript Imports Plugin
This plugin allows the use of bash-script-based imports with PolyScript. Note: only works on systems where bash is available on the PATH (eg. Linux, MacOS, some versions of BSD, or Msys2/Cygwin)

This plugin allows the use of bash scripts for importing variables.

## Compiling
Compiling the plugin can be done using polytool and using gradle, first, make sure to have restored the base `polyscript-engine` project, see its README for info.

While `polytool build` will build all projects including the plugin, you can compile this plugin manually using `./gradlew plugin-shellscript:build` in the root project (`polyscript-engine`), once built, it can be found under `<plugin-shellscript>/build/libs`.

Unlike the git plugin, the shellscript plugin is a single jar that can be installed directly.

## Installing plugin
Simply copy the assembly (not javadoc or sources) jar file from `<plugin-shellscript>/build/libs` into your tool's plugins folder, there are no additional dependencies required.

## Enabling the plugin
Please do note that to use the plugin, you will need to have added the jar to the plugins folder of your tool.

Once thats ready, add the following to your root script, eg. to `build.settings.json` to:
```json
{
    // ...

    // Plugins
    "plugins": [
        // ...

        // Add shellscript imports plugin
        "shellscript-imports"

        // ...
    ]

    // ...
}
```
Once enabled, the `shellscript` importer can be used.

## What this plugin provides
This plugin provides an importer `shellscript` that can be used to import bash scripts as variables using Environment Helper scripts.

Basically, the shellscript importer creates a temporary script that wraps around the imported script, and using a Environment Helper, passes the imported variables back to the polyscript engine.

## How Shellscript imports work
Shellscript imports work by the plugin creating a Wrapper Script at runtime, which contains the calls to source the given import script into the bash instance.

Using the Environment Helper, the import will be able to give variables to the script engine through specific calls.

## What are Environment Helpers
To be able to export variables from a script, you will need to write an environment helper script. Environment helper scripts are scripts loaded onto the script engine prior to evaluating the import script, that provide logic for exporting variables.

The process structure works somewhat like this:
- Script Engine
  - Bash instance
    - Wrapper script (generated by plugin)
      - Environment helper - Preload (eg. setting up environment)
      - Imported script (the script being imported)
      - Environment helper - Emitter (emitting the variables)

Environment Helpers are used to export variables from the script using bash functions `pushVariable()` and `pushArrayElement()`, which tell the shellscript plugin which variables to define.

They can also be used to set up an environment prior to evaluating the imported script, eg. specific default variables, adding bash functions, loading scripts, etc.

## Using the Shellscript Importer

### Setting up imports
First you will need to add a importer statement to add the shellscript importer to the engine, make sure to have the plugin applied prior:
```json
{
    // ...

    // Importers
    "importers": {
        // Eg. sh files
        "*.sh": "shellscript",

        // Eg. bash files
        "*.bash": "shellscript",

        // Eg. polyfile (bash) files
        "*.pcb": "shellscript"
    }

    // ...
}
```

After defining importers, imports can be defined to import shellscript files:
```json
{
    // ...

    // Imports
    "import": [
        "examplefile.sh"
        "some/path/to/example2.sh"
    ]

    // ...
}
```
Defining the imports will make the script engine load the scripts.

### Defining Environment Helpers
To be able to assign variables, you will need to set up Environment Helper scripts.

Environment Helpers will let the underlying bash instance know which variables to pass to the engine. Environment Helpers are scripts that are defined for each import that are loaded onto the bash instance prior to sourcing the import.

Each environment helper is bound to the import string of the given import.

Environment Helpers can be defined through the `shellenv` block:
```json
{
    // ...

    // Shell Environment
    // Each value must match an import in the import block
    "shellenv": {
        // For `examplefile.sh`
        // We can have multiple helpers,
        // they are loaded in order.
        "examplefile.sh": [
            "util/import1.sh",
            "util/import2.sh"
        ],

        // For `example2.sh`
        "some/path/to/example2.sh": "util/example2.sh"
    }

    // ...
}
```
Each helper script is loaded relative to the script importing it.

### Creating Environment Helpers
Environment helpers are script files loaded by the engine relative to the script adding the helpers.

Example script:
```bash
# Setup event
# This function is called to create the environment
# Called prior to importing
function setup() {
    # Assign variables
    examplestring="Default value"
    examplenumber=1
    examplearray=()
}

# Variable emitter event
# Used to write variables to the engine
# During this event, the variable emitter calls are available
# Called when the import script has been sourced
function emitvars() {
    # Write variables to engine
    pushVariable "examplestring" "$examplestring"
    pushVariable "examplenumber" "$examplenumber"

    # Write array elements
    # The function pushArrayElement can add elements to a json array
    for ele in "${examplearray[@]}"; do
        pushArrayElement "examplearray" "$ele"
    done
    
}

# Finish event
# This function is called to clean up the environment
# Called after variables have been emitted
function finish() {
    # Clean up
    examplestring=""
    examplenumber=1
    examplearray=()
}
```
